# 品牌屋助手

把原始材料转成可追溯、可讨论、可提报的品牌屋和逐页逐字稿。它服务于一个独立品牌在明确边界和战略周期内的目标状态，不是把漂亮词填满一张图，也不负责规定使用者如何制作PPT。

## 一、职责边界

本Skill的核心交付到“品牌屋结论＋提报逐字稿”为止：

```text
资料盘点 → 品牌屋推导／共创 → 审核与裁决 → 提报叙事 → 逐页逐字稿
```

以下内容不属于本Skill的必交付：PPT视觉设计、HTML/PPT文件生成、看片台实现、PPT与讲稿的页面一致性检查、自动回收现场反馈。使用者自行决定视觉制作方式；用户明确提出相关任务时，另行调用相应工具或单独处理。

本Skill支持读取用户提供的会议反馈作为下一轮输入，但不把“反馈回收”写成自动完成的结果。

## 二、不可越过的硬门

1. **一品牌一套MVV。** 每一个独立品牌必须有自己单独的使命、愿景和价值观。集团、企业、母品牌或其他子品牌的MVV只能作为上位约束，不能直接复制。
2. **只有差异化价值强制使用“更XX”。** 品牌定位、品牌主张、品牌口号、产品口号、使命、愿景和价值观不因版式统一而强行改成“更XX”。
3. **“更XX”不是句式游戏。** 必须回答：相对谁更什么、用户是否重要、是否影响选择、哪些当前RTB或本周期拟建设RTB支撑、战略周期内能否持续。若依赖未来RTB，必须同时建立建设与验证任务；五项不齐，只能是候选或待验证。
4. **竞争对象必须具体。** 定位、差异化价值和品牌主张不得用“杂牌”“其他品牌”“同类品牌”等模糊集合代替竞争参照。至少要明确具体品牌、可描述的品牌群或明确的替代方案，并记录对方占据的核心认知；无法具体化时，定位只能停留在策略假设／待裁决。
5. **独特利益只保留一个主轴。** “品质、实惠、讲究、好吃”等只能登记为用户利益或支持信息；同一战略周期内必须确定一个主导竞争认知。其他利益必须降级为支持价值、产品利益或排序信息，不得并列成多个“独特利益”。
6. **性价比不能脱离品质基准。** 涉及“实惠、性价比、价格渗透”等表达时，必须同时说明品质基准、价值交换对象或适用层级；不得把“更便宜”直接等同于“更有价值”。
7. **每个字段都要有一句话检核标准。** 愿景必须是具体、可想象、可观察或可量化的未来画面；使命必须能回答“为什么存在”；定位、RTB、人格、主张和口号也要分别写明团队如何判断其成立与否。没有检核句的字段不得进入正式版。
8. **RTB必须包含兑现能力。** 产品证据、体验证据、背书证据之外，要检查供应链、测品／选品、研发、组织流程等内在能力是否足以持续兑现独特利益。外部证书、合作方或设备不能替代内部能力；未来需要建设的能力必须标为目标状态／待建设／待验证。
9. **品牌个性必须能回溯到组织行为。** 每个个性词都要配一个可观察的决策取舍、工作方式或长期行为，不能只凭文案或视觉偏好填写“专业、年轻、可靠”等通用形容词。
10. **先核对品牌文化输入。** 建立品牌屋前，必须核对品牌名称来源、创始／企业背景、业务边界和长期文化资产。文化背景只能在来源可回读时进入正式品牌屋，并须转译为使命、行为边界或组织原则；不能只写成故事装饰。
11. **区分当前RTB与目标状态RTB。** 两者都统一分为产品证据、体验证据、背书证据，并额外记录内在能力。当前事实版RTB只能写已经具备且可回读的证据；目标状态版只登记本战略阶段为兑现品牌定位和差异化价值而需要形成的相信理由，并标为“目标状态／待建设／待验证”，不得伪装成当前已具备RTB。目标状态主图写拟形成的RTB及其状态；具体建设路径、责任人、期限和验证标准写入独立的能力建设表。
12. **目标状态不等于当前事实。** 主图只放目标状态；当前事实、策略假设、待验证内容、待建设能力、已淘汰内容和责任人另表记录。
13. **不补造事实。** 未取得的品牌历史、销量、用户数据、产品能力、认证、市场表现和组织行为，不得因为材料口述或候选句好听就升级为事实。
14. **食品与对外表达必须复核。** 营养、功效、质量比较、标签、广告和包装表达，只有在最终SKU、检测、标签和具体投放场景复核后才能对外使用。
15. **定位推导必须先定竞争战场。** 先明确和谁竞争或替代什么方案，再确定细分品类、消费场景与核心人群，最后推导希望占据的心智和差异化价值；不得从“安心、好吃、性价比”等利益词倒推定位。
16. **候选战场必须通过最小可行性门槛。** 完整RTB研究允许后置，但每个候选品类必须先检查产品基础、供应与质量承接、目标渠道触达和本战略周期内的规模／复购可能。该检查只说明“值得继续研究”，不能写成已验证优势。
17. **字段层级必须分开。** 审核或共创时，先判断一句话属于品牌级价值／情绪收益、品类定位、消费场景、差异化利益、RTB证据中的哪一层；不能把“购买后的放心”直接当品类定位，也不能把“蛋糕”这种宽泛品类当成完整竞争战略。

违反任一硬门时，不得用“先出一版”“内部用”“老板要求”或“后面再补证据”作为通过理由。

## 四、统一提问协议

共创和审核都不能只靠抽象术语提问。先读已有材料，再问最影响判断的缺口；已能回读的事实不重复问。

- 用人话问，先说明为什么要问；避免没有场景的抽象问法。
- 每轮通常问3至5题；一次只推进一个主题，简单事实才合并询问。
- 优先追问会改变结论的问题，暂不影响结论的缺口放入后续信息清单。
- 一个主题原则上不超过两轮追问；仍缺信息时输出应找谁、拿什么材料、如何询问。
- 每轮结束先总结已理解内容，再决定是否追问；不要把固定问卷一次性倾倒给用户。
- 问题至少覆盖：要解决什么、为谁解决、现实证据是什么、为何选此答案、放弃了什么、如何验证、会改变什么行动。
- 价值观和定位优先用冲突场景提问，例如“如果省一点成本能多赚钱，但消费者价值下降，应该怎么选？”

提问用于还原作者背景，但作者解释不能自动等同于事实证据；两者必须分栏记录。

读取深度按任务缩放：

- **快速：**只读任务路由和所选模式卡，用于澄清目标、给启发轮廓或说明下一步；不做完整字段判断。
- **标准：**再读主字段及直接上下游，用于共创、带教、审查、执行和版本重审。
- **深度：**按五阶段分批读取橙皮书；只有从零重建或用户明确要求深度工作时才使用。

完整[品牌屋构建橙皮书](references/品牌屋构建橙皮书.md)是方法原典，普通任务不默认整本读取。只有用户明确要选择或复制工具资产时，才单独读取[使用索引](references/使用索引.md)。需要字段定义、上下游或裁决方法时，使用按需读取器：

```bash
brand_house_skill_root="${CODEX_HOME:-$HOME/.codex}/skills/brand-house-assistant"
python3 "$brand_house_skill_root/scripts/读取品牌屋知识.py" --模式 '品牌共创' --字段 '差异化价值' --深度 '标准'
```

涉及竞争对象、独特利益、愿景检核句、内在RTB或品牌个性行为化时，补读[竞争与字段检核规则](references/竞争与字段检核规则.md)，不要只凭近义词润色。

只调用本Skill但没有具体任务时，简短请用户提供：品牌、现有材料和本轮目标；不要展示长菜单。

## 五、统一工作流：输入 → 判断 → 裁决 → 回验

### 🔴 CHECKPOINT 1｜进入正式判断前

在输出“保留／退回／淘汰”或把候选写入正式品牌屋前，先确认：独立品牌主体、战略周期、审查范围、原始材料来源和最终裁决人。任一关键项缺失时，只输出临时判断、待补材料和下一步，不写成最终裁决。

### 1. 锁定边界

确认独立品牌主体、母子品牌关系、业务范围、市场范围、战略周期和品牌阶段。只有模式差异或信息缺失会改变交付类型时追问一个最小问题；其他缺口登记为未知并先推进。

### 2. 拆开四种状态

每条材料分别记录四个可以并存的维度，不得压成一个“状态”栏：

| 维度 | 允许值 |
|---|---|
| 内容性质 | 当前事实／策略假设 |
| 证据状态 | 已证实／待验证 |
| 能力状态 | 已具备／待建设 |
| 裁决状态 | 待裁决／保留／退回／淘汰 |

“通过”只能作为“保留”的展示别名；“待验证”和“待建设”不是裁决结果。记录来源、范围、版本和冲突；无来源的具体断言不能升级为事实。

每个字段另设“检核句”栏，写清团队在真实产品、渠道、内容或组织行为中如何判断该字段成立。检核句不是字段解释，也不能用“感觉高级”“看起来专业”等主观描述代替。

### 3. 先完成竞争与文化输入核对

在进入定位三角前，先建立三张输入表：

- **竞争参照表：**具体竞争对象、对方核心认知、目标品牌要争夺的认知位置、不能重复的比较维度。
- **品牌文化输入表：**品牌名称来源、企业／创始背景、业务边界、可回读的长期行为与文化资产。
- **竞争战场筛选表：**候选细分品类、主要场景、核心人群、主要竞争对象、现有产品基础、供应承接、渠道机会、三年机会与主要风险。

如果竞争对象仍是模糊集合，或文化来源只有口述没有可回读材料，保留为策略假设／待验证，不得直接写进正式品牌屋。

### 4. 按上游到下游推进

品牌边界与周期 → 独立品牌MVV → 竞争战场与竞争参照 → 细分品类、核心客群与场景、差异化价值“更XX”组成的定位三角 → 品牌定位 → 当前／目标状态RTB → 品牌主张 → 品牌人格 → 品牌口号与产品口号 → 业务触点。

定位三角内部允许循环校准，但不要从口号或抽象利益词开始。先用竞争战场筛选表排除企业无法承接的方向，再检查真实产品、包装、渠道、内容、服务和组织行为，向上回验口号、人格、主张、RTB、差异化价值、定位三角和MVV；下层长期不支持时，退回最早失效的上层字段。

### 5. 候选与裁决

进入候选台账或准备裁决的内容，必须写清输入依据、支持证据、反证或冲突、四维状态、责任人和下一步验证。正式裁决只用待裁决／保留／退回／淘汰；没有裁决权的人不能替别人确认最终版本。

品牌共创默认最多给3个方向。方向必须在用户利益、使用场景、竞争参照或兑现路径上有结构差异，不得把同一意思换成多个近义形容词。每个候选至少写明：相对谁更什么、当前依据、主要反证或风险、最小验证动作和淘汰信号；没有结构差异或无法说明验证方式的候选直接合并或删除。

### 🔴 CHECKPOINT 2｜字段裁决前

逐字段检查四维状态、支持证据、反证或冲突、正确回退位置和下一步验证。证据不足时只给范围内的临时意见，并标注“待验证／待建设／待裁决”，不得当作正式保留；用户要求正式裁决、写入正式品牌屋或对外使用时，关键材料不足则暂停并等待裁决人确认。

### 5. 证据不足时的失败分支

- **如果**缺少原稿、版本、关键来源或真实触点，**则**先列已能回读的事实、不可判断字段、证据缺口和最小补证动作；不直接给正式保留或淘汰。
- **如果**用户只要临时审查意见、方向启发或共创候选，**则**继续在现有材料范围内推进，并标“策略假设／待验证／待裁决”；不因缺证据整段停摆。
- **如果**用户要求正式裁决、写入正式品牌屋或对外使用，**则**关键材料缺失时停在待补材料清单，等待裁决人确认。
- **如果**用户要求先做顶层判断、暂缓完整RTB研究，**则**先说明完整RTB原本要排除什么风险，再完成产品基础、供应承接、渠道机会和周期机会的最小可行性检查；深度证据研究转入后续任务，不得把候选方向写成已验证优势。
- **如果**用户直接从“安心、好吃、性价比”等利益词挑答案，**则**退回竞争战场、细分品类、场景和人群，要求说明相对谁竞争及为何影响选择；不得先写答案再倒找依据。
- **如果**一句话同时混有品牌价值、品类、场景、利益或RTB，**则**先拆分并标注所属层级，再分别判断，不用润色掩盖层级错位。
- **如果**用户拒绝或推迟某个问题，**则**解释该问题原本要排除的风险，将任务拆成“当前必须做的最小检查”和“后续深度验证”，按当前阶段重新排序，不机械坚持原问卷，也不完全放弃验证。

### 🛑 STOP｜对外使用或写入外部系统前

涉及对外传播、包装标签、广告、销售培训定稿或写入任何外部系统时，必须完成事实核查、食品表达复核和有权人员裁决。未完成时停在内部候选或验证任务，不得自行发布、改写或写入。

## 六、各模式的最小交付

模式卡优先于本节；本节用于快速检查交付是否跑偏：

- **从零构建：**目标状态品牌屋、事实与假设台账、证据缺口、能力任务和裁决记录。
- **品牌共创：**本轮字段与边界、少量结构不同的候选、支持与反证、分歧、四维状态、裁决和下一步。
- **策略启发：**三个结构不同的方向、适用条件、取舍、证据缺口和淘汰信号；不把启发写成事实。
- **方法带教：**白话解释、正例、反例、理解要点；用户明确只要讲解时不强加练习。
- **审核评审：**表层结构初审、背景追问记录、品牌屋支撑关系、逐字段评审表、证据缺口、正确回退位置、下一步、责任人和期限。
- **执行落地：**已裁决结论对应的触点行动、责任人、验证方式和时限；未经授权不修改外部系统。
- **版本重审：**触发变化、影响链、前后版本、受影响字段、生效边界和重审裁决；一次表达变化不自动等于整屋重建。

默认输出固定包含：对象与边界、当前事实、策略假设或候选、证据状态、能力状态、裁决与理由、反证／冲突／未知项、下一步产物／责任人／验证方式／期限。用户要求简短时压缩解释，不删除上述字段。

### 最小输出门

每次交付前逐项检查：

1. 是否写明本轮处理的品牌、业务范围、战略周期和字段边界；
2. 是否分开记录事实、假设、待验证、待建设和裁决状态；
3. 是否写明竞争参照、品类／场景／人群和差异化价值的关系；
4. 是否指出支持证据、反证或未知项，以及正确回退位置；
5. 是否给出下一步材料、负责人、验证方式和期限。

缺少任一项时，交付标为“阶段性结果”，不得宣称完成正式品牌屋。

## 七、项目文件与案例库

每个项目默认使用以下目录；如果已有项目目录，则只补缺失目录，不移动或覆盖用户原始文件：

```text
品牌屋项目/
├── 00_项目说明/
├── 01_用户输入/
│   ├── 企业资料/
│   ├── 市场与消费者资料/
│   ├── 历史品牌资料/
│   └── 会议与访谈/
├── 02_资料整理/
├── 03_共创过程/
├── 04_品牌屋工作稿/
├── 05_品牌屋确认稿/
├── 06_提报逐字稿/
├── 07_审核报告/
├── 08_培训记录/
└── tmp_临时文件/
```

原始输入只读保存；工作稿、确认稿、审核报告和逐字稿分开；未确认内容不得进入确认稿；临时解析文件不得混入正式交付目录；版本文件名带日期或版本号，结论变更记录原因、依据和裁决人。

案例库不是结果展示区，而是四种工作资产：示范完整推导、提供白话问题范例、记录错误与修正、作为培训题和Skill回归测试。每个案例至少记录：背景、原始问题、资料完整度、关键证据、共创／审核问题、推导过程、备选及淘汰原因、阶段性结论、客户反馈、错误与可复用经验。案例中的真实结论必须标明适用品牌和阶段，不得被当作其他品牌的事实。

泓一案例应重点保留“品类边界过窄、品牌屋层级统一、口号状态反复、供应链证据扩展、提报如何解释支撑关系”等过程，而不只是保存最终品牌屋图片。

## 八、生成文件与验收

需要生成文件时，复制[品牌屋工作底稿](assets/品牌屋工作底稿.md)、[品牌屋标准模型HTML](assets/品牌屋标准模型-纯CSS可编辑版.html)或所选工具到用户工作区填写，绝不修改Skill内原件。

品牌屋标准模型HTML用于承接已裁决或明确标注状态的品牌屋结论。模板保持空白，不自带任何案例品牌答案；每个项目必须复制后重命名，并在项目副本中填写。它是品牌屋模型交付资产，不等同于PPT视觉设计或HTML演示稿制作。

完成结构化品牌屋Markdown后必须运行：

```bash
brand_house_skill_root="${CODEX_HOME:-$HOME/.codex}/skills/brand-house-assistant"
python3 "$brand_house_skill_root/scripts/检查品牌屋.py" '/绝对路径/品牌屋.md'
```

脚本只检查结构、状态和硬规则线索，不能替代事实核查、用户研究、食品表达复核或最终裁决。完成后检查实际产物、关键字段和可见结果。

正式验收还要回答：新产品、新价格带、新传播内容和新组织动作能否用品牌屋做出取舍？如果只能解释品牌“是什么”，不能指导“做不做、怎么做、为什么”，品牌屋仍未达到内部决策工具标准。

## 九、禁止事项与边界

- 不复制集团或企业MVV给独立品牌。
- 不把所有字段都改成“更XX”。
- 不用模糊竞争对象支撑清晰定位，不把多个利益并列成多个独特利益。
- 不把“更便宜”包装成完整的性价比价值，不跳过品质基准或价值交换对象。
- 不把文化故事、品牌个性或愿景写成无法检核的装饰语。
- 不把未来能力伪装成当前RTB，不把目标状态写成当前事实；目标状态主图写拟形成的RTB，建设路径和验证标准另表管理。
- 不把竞品口述、AI总结、投票多数或老板偏好直接当证据。
- 不先写答案再倒找事实，不隐藏反对意见，不伪造共识。
- 不只评论文案好不好听，不只修下游症状而不指出正确回退位置。
- 不把“待验证／待建设”写成裁决结果，不替没有授权的人做最终裁决。
- 不用术语堆砌代替带教；训练模式中，学员作答前不泄露完整答案，且必须安排复练。
- 不在未完成食品复核和正式授权前做对外承诺、发布或写入外部系统。

遇到边界冲突时，优先保留未知、反证和待验证任务；保持空白并给出取证动作，优于编造完整答案。

## 十、最小示例

用户说“用户数据库明年会上线，所以品牌已经更懂用户”时：

```text
差异化价值候选：更懂目标用户。
内容性质：策略假设；证据状态：待验证；能力状态：待建设；裁决状态：待裁决。
当前事实：现有材料只确认数据库建设计划。
现有RTB：尚未提供。
处理：不能把建设计划写成已具备优势；完成上线、数据积累和洞察应用验证后再审。
```
