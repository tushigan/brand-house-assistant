## 完整构建的五个阶段

1. 边界与总模型：§01—§03。
2. 独立MVV：§04—§06。
3. 定位与证据：§07—§11。
4. 品牌表达：§12—§15。
5. 项目落地：§16—§18。

每完成一个阶段，都先产出状态与证据清单，再进入下一阶段。定位三角的三角字段需要循环校准，不能机械单向填写。

## 工具目录

配套模板位于`assets/工具/`：

- 01—03：品牌边界、材料审计、阶段分流。
- 04—06：MVV访谈、真实性审计、价值观故事与红线。
- 07—10：品类语言、客群场景、“更XX”、定位三角与主图。
- 11—15：RTB、品牌主张、人格、品牌口号、产品口号。
- 16—20：业务转译、状态与能力、一致性验证、版本重审、AI辅助。

完整品牌屋需要形成可编辑模型时，复制`assets/品牌屋标准模型-纯CSS可编辑版.html`到项目目录后再填写。该文件只保留通用结构与编辑能力，不含任何案例品牌答案；不要直接修改Skill内原件。

工具09的自动计算只负责结构门禁。最终差异化价值必须由用户选择影响、真实比较对象、当前RTB或本周期拟建设RTB（明确标注目标状态／待建设／待验证）和持续性共同决定。

## 案例查询

用户问“最佳实践”“案例”“范例”时，先读取 `案例库/README.md`，再读取匹配案例全文。不要把测试提示词当成范例，也不要因为案例文件使用了脱敏名称就把它当成另一品牌的事实。案例只用于学习推导、提问、证据处理和提报讲法。

## 标题检索

从当前Agent实际加载的Skill目录运行。不要把下面的路径写死为某一个Agent框架：

```bash
skill_root="<当前Agent实际加载的brand-house-assistant目录>"
rg -n '^# §09 |^## 9\.' "$skill_root/references/品牌屋构建橙皮书.md"
rg -n '使命|愿景|价值观' "$skill_root/references/品牌屋构建橙皮书.md"
rg -n '当前事实|策略假设|待验证|待建设|已淘汰' "$skill_root/references/品牌屋构建橙皮书.md"
```

需要引用方法时，优先回到章节原文；本索引只负责路由，不替代完整方法。
