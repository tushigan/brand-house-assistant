# brand-house-assistant 跨框架安装与运行

## 核心原则

`brand-house-assistant` 的正文、案例和工具不绑定某个 Agent 产品。安装和更新时，当前 Agent 只能使用自己实际加载的 Skill 根目录；不要读取或覆盖其他 Agent 的目录。

## 安装／更新流程

1. 从 `https://github.com/tushigan/brand-house-assistant` 读取最新 Release 或 Git 标签。
2. 让当前 Agent 识别自己的用户级 Skill 根目录。优先使用框架提供的路径变量或官方约定；没有变量时，以当前运行环境实际加载的 Skill 目录为准。
3. 在该根目录查找 `brand-house-assistant/VERSION`。
4. 目录不存在：安装最新稳定版本。
5. 目录存在但版本更旧或没有版本文件：先把整个目录备份到该 Skill 根目录同级的 `skills-backups/brand-house-assistant/<时间戳>/`，再替换。
6. 版本已是最新或更高：不覆盖，只报告当前版本。
7. 替换前核对 `SKILL.md`、`references/`、`assets/`、`scripts/`、`案例库/` 和 `test-prompts.json`；替换后核对 `VERSION`、关键脚本和目录结构。
8. 重启或重新打开当前 Agent，并在新对话中调用 `$brand-house-assistant` 验证已生效。

## 路径说明

- 不要在 Skill 正文中写死 `~/.codex`、`CODEX_HOME` 或任何其他特定框架目录。
- 不同框架可以有自己的用户级目录、项目级目录和适配元数据；只使用当前框架的目录约定。
- `agents/openai.yaml` 是可选的 OpenAI/Codex 适配文件，其他框架可以忽略并直接读取 `SKILL.md`。
- 备份目录必须在当前 Skill 根目录之外，不能让旧版本继续作为同名 Skill 被加载。

## 脚本调用

把 `skill_root` 设为当前 Agent 实际加载的本 Skill 目录，再调用脚本：

```bash
skill_root="<当前Agent实际加载的brand-house-assistant目录>"
python3 "$skill_root/scripts/读取品牌屋知识.py" --模式 '品牌共创' --字段 '差异化价值' --深度 '标准'
python3 "$skill_root/scripts/检查品牌屋.py" '/绝对路径/品牌屋.md'
```

不要从另一个 Agent 的安装目录复制脚本，也不要为了运行脚本自行猜测路径。
